# deshiQR architecture & internal contract

This document is the internal contract for the repo. Every package, app and doc in here is built against it.

## 1. What deshiQR is

deshiQR turns the **Bangla QR** payment payload (the NPSB/EMVCo QR format used by bKash and other
Bangladesh wallets and banks) into a small, boring, dependency-free toolkit:

- `deshiqr` — parse, verify, derive and build payloads (zero dependencies, runs anywhere).
- `deshiqr-qr` — QR encoder + SVG/terminal renderer (zero dependencies).
- `deshiqr-element` — `<deshiqr-pay>` web component for embedding.
- `apps/web` — static-first hosted pay pages, setup wizard, printable posters, and a
  Supabase-powered dashboard.
- `supabase/` — schema, RLS policies, and an invoice edge function.

### Provider support matrix

Every QR here is a standard **Bangla QR** payload. A QR generated by deshiQR can be paid from any
app that accepts Bangla QR.

| Provider | Scan & pay a deshiQR QR | Decode / derive in deshiQR | Notes |
| --- | --- | --- | --- |
| bKash | Yes | **Verified today** | Payloads decoded against real bKash QRs; pinned by tests |
| Nagad | Yes, if the app accepts Bangla QR | Planned | Needs real sample payloads before we claim support |
| Rocket | Yes, if the app accepts Bangla QR | Planned | Needs real sample payloads |
| Bank / NPSB apps | Yes, if the app accepts Bangla QR | Planned | Shared `bd.org.bb.npsb` account template |
| Other Bangla QR wallets | Depends on the app | Planned | Generic parser, unverified |

**Verified** means we have decoded and derived real payloads from that provider and our tests pin
the behaviour. **Planned** means the parser is provider-agnostic but we have not validated real
payloads yet, so we do not claim support. Do not overstate this in any README, doc, UI copy or
metadata.

### Data policy (hard rule)

**No real merchant or payment data is ever committed to this repo.** All fixtures, seeds, examples
and docs use the synthetic payloads in [`docs/demo-payloads.md`](./demo-payloads.md): fake account
`01000000000` (unassignable operator prefix), name `DEMO STORE`, city `Dhaka`, and dummy NPSB
tokens. Tests must never be generated from a real merchant QR.

## 2. Repo layout

```
packages/core       → npm: deshiqr          (payload library)
packages/qr         → npm: deshiqr-qr       (QR encoder + renderers)
packages/element    → npm: deshiqr-element  (<deshiqr-pay> web component)
apps/web            → @deshiqr/web          (Vite static app, Netlify/Pages deployable)
supabase/           → schema.sql, seed.sql, functions/invoice (Deno edge function)
examples/           → vanilla / React / Node integration examples
docs/               → public documentation
scripts/            → repo tooling (edge vendoring, SQL checks)
```

Workspace: pnpm. Node >= 22.18. TypeScript >= 5.9, strict.

## 3. `deshiqr` (packages/core) — public API

Zero runtime dependencies. Environment-agnostic: browsers, Node, Deno, edge runtimes.

```ts
export const VERSION: string;                       // package version
export const MAX_AMOUNT: number;                    // 99_999_999.99
export const TAGS: Record<"VERSION"|"POI"|"ACCOUNT"|"MCC"|"CURRENCY"|"AMOUNT"|"COUNTRY"|"NAME"|"CITY"|"ADDITIONAL"|"CRC"|"TOKEN80"|"TOKEN81", string>;

export type DeshiQrCode =
  | "EMPTY_PAYLOAD" | "BAD_TLV" | "CHECKSUM_MISMATCH" | "MISSING_FIELD"
  | "NOT_A_BANGLA_QR" | "BAD_AMOUNT" | "BAD_REFERENCE" | "UNSUPPORTED";

export class DeshiQrError extends Error {
  readonly code: DeshiQrCode;
  readonly detail?: string;
}

export interface Field { tag: string; value: string }

export function crc16(input: string): string;                // "29B1"
export function parse(payload: string): Field[];             // throws DeshiQrError
export function encodeField(field: Field): string;
export function encodeFields(fields: Field[]): string;

export interface MerchantDetails {
  name: string;            // tag 59
  city: string | null;     // tag 60
  account: string;         // template 26 / sub-tag 03
  institution: string;     // template 26 / sub-tag 00, e.g. "bd.org.bb.npsb"
  mcc: string | null;      // tag 52
}

export interface DecodedQr {
  payload: string;
  kind: "static" | "dynamic";     // from tag 01 (11 / 12)
  amount: number | null;          // tag 54, in BDT
  amountText: string | null;      // tag 54, raw e.g. "500.00"
  currency: string | null;        // tag 53 mapped, e.g. "BDT"
  country: string | null;         // tag 58, e.g. "BD"
  merchant: MerchantDetails;
  reference: string | null;       // template 62 / sub-tag 01
  customerLabel: string | null;   // template 62 / sub-tag 06
  additionalData: Field[];        // template 62 subtree
  accountTemplate: Field[];       // template 26 subtree
  tokens: { tag80: string | null; tag81: string | null };  // opaque NPSB tokens, preserved verbatim
  fields: Field[];                // top-level fields
  checksum: string;
}

export function decode(payload: string): DecodedQr;          // throws on any error
export function decodeSafe(payload: string):
  | { ok: true; qr: DecodedQr }
  | { ok: false; error: DeshiQrError };
export function verifyChecksum(payload: string): boolean;
export function isBanglaQr(payload: string): boolean;

export interface DeshiQrIssue { code: DeshiQrCode; message: string; tag?: string }
export interface ValidationReport {
  ok: boolean;                    // no errors (warnings allowed)
  errors: DeshiQrIssue[];
  warnings: DeshiQrIssue[];
  qr: DecodedQr | null;           // best-effort decode when possible
}
export function validate(payload: string): ValidationReport;

// Derivation
export interface AmountOptions {
  reference?: string | null;           // explicit reference to embed
  referencePrefix?: string;            // used when generating a reference
  referenceLength?: number;            // 0 = no reference (default: keep existing length)
  keepExistingReference?: boolean;     // default false
}
export interface BuildOptions extends AmountOptions {
  amount?: number | null;              // null/undefined = static payload
}
export function toStatic(payload: string): string;                       // drop amount + reference, tag 01 → 11
export function withAmount(payload: string, amount: number, options?: AmountOptions): string;
export function build(base: string, options?: BuildOptions): string;
export function referenceFrom(payload: string): string | null;
export function newReference(options?: { prefix?: string; length?: number }): string; // default length 25 (bKash bill-number shape)
export function amountToField(amount: number): string;   // 500 → "500.00"
export function parseAmountField(text: string): number;  // "500.00" → 500
export function formatTaka(amount: number, options?: { symbol?: boolean; decimals?: number }): string;
export function maskAccount(account: string): string;    // "01000•••000"
export const KNOWN_INSTITUTIONS: Record<string, { id: string; label: string; verified: boolean }>;
export function institutionOf(qr: DecodedQr): { id: string; label: string; verified: boolean } | null;
```

Derivation rules (must match the behaviour of the original working app so existing links keep working):

1. Start from the parsed fields, drop tag `63` and any existing tag `54`.
2. `toStatic`: set tag `01` to `11`, drop sub-tag `01` from template `62`, re-seal.
3. `withAmount`: set tag `01` to `12`, insert `54` = `amount.toFixed(2)` immediately before the
   first top-level tag numerically greater than `54`, add/replace template `62` sub-tag `01` when a
   reference is requested, re-seal.
4. Everything else (template `26`, MCC `52`, currency `53`, country `58`, name `59`, city `60`,
   NPSB tokens `80`/`81`, other `62` sub-tags) is preserved **verbatim**.
5. Re-seal by appending `"6304"` and the uppercase CRC-16/CCITT-FALSE of the payload so far.

Validation must be strict about the checksum and required fields, lenient about optional ones
(collect them as warnings, never throw in `validate`).

## 4. `deshiqr-qr` (packages/qr) — public API

QR Code encoder (ISO/IEC 18004), byte mode, versions 1–40, EC levels L/M/Q/H, automatic version and
mask selection. Zero runtime dependencies.

```ts
export type EcLevel = "L" | "M" | "Q" | "H";
export type RawText = string;

export interface QrMatrix {
  size: number;              // modules per side
  version: number;           // 1..40
  level: EcLevel;
  mask: number;              // 0..7
  data: Uint8Array;          // size*size, 1 = dark, row-major
  get(x: number, y: number): boolean;
}

export interface EncodeOptions {
  level?: EcLevel;           // default "M"
  version?: number;          // force version; default auto
  minVersion?: number;
  mask?: number;             // force mask 0..7; default auto (penalty)
  eager?: boolean;           // skip minimal-version search (internal use)
}

export function encode(text: string, options?: EncodeOptions): QrMatrix;
export function getVersionCapacity(version: number, level: EcLevel): number; // byte capacity

export interface SvgOptions {
  margin?: number;           // default 4
  scale?: number;            // default 1 (1 module = 1 unit)
  dark?: string;             // default "#000"
  light?: string | null;     // null = transparent; default "#fff"
  title?: string;            // accessible <title>
  radius?: number;           // quiet-zone corner radius, default 0
  className?: string;
  ariaLabel?: string;
}
export function toSvg(matrix: QrMatrix, options?: SvgOptions): string;
export function toSvgPath(matrix: QrMatrix, options?: SvgOptions): string; // <path d="..."/>
export interface TerminalOptions { margin?: number; dark?: string; light?: string }
export function toTerminal(matrix: QrMatrix, options?: TerminalOptions): string;
```

`toSvg` output must be a complete, self-contained `<svg>` string with `viewBox`, no external
references, no scripts, and deterministic output (no timestamps/ids).

## 5. `deshiqr-element` (packages/element) — public API

Custom element, shadow DOM, zero runtime dependencies (bundles `deshiqr` + `deshiqr-qr`). ESM build
plus an IIFE global bundle (`dist/deshiqr-element.global.js`, global `DeshiQrElement`). Registering
`<deshiqr-pay>` happens on module import; the IIFE build registers automatically.

```html
<deshiqr-pay
  payload="00020101021126…"      <!-- static base payload (required unless config-url) -->
  config-url="https://…/config.json" <!-- optional JSON config: {base_payload,title,note,presets,ref_prefix,ref_len} -->
  amount="500"                   <!-- optional; when omitted the user types an amount -->
  lock-amount                    <!-- optional boolean -->
  reference="DEMOQR0VZeK2MfbVRI6w36osd" <!-- optional explicit reference -->
  ref-prefix="FT80"              <!-- optional generated reference prefix -->
  ref-length="25"                <!-- optional generated reference length; 0/absent = none -->
  title="Demo Store"
  note="Pay before 6pm"
  presets="100,500,1000"
  theme="auto|light|dark"
  size="280"                     <!-- QR px size -->
  bare                           <!-- optional: no card chrome -->
></deshiqr-pay>
```

Methods: `refresh(): void`, `setAmount(amount: number | null): void`, `getPayload(): string`,
`getSvg(): string`, `downloadPng(filename?: string): Promise<void>`.
Events (bubbles, composed, dispatched on the element):
- `deshiqr-ready` `{ payload, amount, reference }`
- `deshiqr-change` `{ amount, payload, reference }`
- `deshiqr-error` `{ code, message }`

Accessibility: amount input has a label; QR has an accessible name; focus styles; reduced-motion
respected. The component must work with no network access when `payload` is provided.

## 6. `apps/web` — routes, config, behavior

Static-first Vite app. Works with **no backend** (demo/local mode) and upgrades to Supabase when
configured. No UI framework, no runtime CDN dependencies.

Routes (client-side; Netlify `_redirects` + `404.html` fallback for deep links):

| Route | Purpose |
| --- | --- |
| `/` | Landing: what it is, live demo, embed snippet, provider matrix, links |
| `/new` | Setup wizard: paste payload / upload QR screenshot (jsQR) / load demo → validate → title, note, presets → live preview → share link, poster, embed snippet |
| `/p/:slug` | Hosted pay page for a published merchant (also `?m=slug` and `#/p/slug` fallbacks) |
| `/@:slug` | Alias for `/p/:slug` |
| `/i/:token` | Hosted invoice page (amount + reference locked, status, customer "I paid" claim) |
| `/dashboard` | Auth-gated merchant dashboard (merchants, links, posters, embeds, invoices, mark paid) |
| `/login` | Magic-link login |

Self-contained links: `/#p=<payload>&t=<title>&pr=<presets>` render a pay page with no backend.
This is the "no account needed" demo path; the payload is public data by nature.

Config resolution order: `window.DESHIQR_CONFIG` → `import.meta.env.VITE_SUPABASE_URL` /
`VITE_SUPABASE_ANON_KEY`. When absent, the app runs in local mode (localStorage) and shows an honest
banner that publishing/accounts need Supabase. Supabase JS is dynamically imported so demo mode never
downloads it.

Design: mobile-first, dark-mode aware, BDT formatting via `deshiqr` helpers, real focus states,
no layout shift, works from `file://`-hosted static builds except for deep links. Copy must state:
bKash verified today, other Bangla QR providers planned, pay with any Bangla QR capable app.

Netlify config: `netlify.toml` + `apps/web/public/_redirects` + `_headers`. GitHub Pages: build with
`DESHIQR_BASE=/deshiQR/`, copy `index.html` → `404.html`, emit `.nojekyll`.

## 7. Supabase + invoice API

Schema and RLS in `supabase/schema.sql`. Public read surfaces expose only public columns (never
`user_id`), only published merchants, and only token-addressed invoices. Writes are owner-only for
merchants; invoice creation and claims go through the edge function / security-definer RPC with
rate limits. The server re-validates the payload CRC before storing it.

Edge function `invoice` (`supabase/functions/invoice/index.ts`), deployed as `invoice`:

```
POST /functions/v1/invoice
  body: { merchant: string, amount: number, note?: string, reference?: string, expires_in?: number }
  201:  { ok: true, invoice: {...}, merchant: {...}, payload: string, pay_url: string, qr_svg: string }

GET /functions/v1/invoice?token=…
  200:  { ok: true, invoice: {…}, merchant: {…}, payload: string | null, qr_svg: string | null }

POST /functions/v1/invoice/claim
  body: { token: string, txid: string }
  200:  { ok: true, status: "claimed" }
Errors: { ok: false, error: { code, message } }
```

The hosted invoice URL is `https://<app-domain>/#/i/<token>` (hash form so static hosts deep-link
correctly) unless the app is configured with a canonical origin.

## 8. Conventions

- TypeScript strict, `verbatimModuleSyntax`, `moduleResolution: bundler`, relative imports use
  explicit `.ts` extensions (Node runs and tests TS directly; bundlers rewrite on build).
- Source of truth is TS source; packages publish ESM + CJS + `.d.ts` via `tsup`.
- Tests: `node --test` with `node:test` + `node:assert/strict`. No test framework dependency.
- No runtime dependencies in `deshiqr` / `deshiqr-qr` / `deshiqr-element` (element bundles its deps).
- Public copy: no overclaiming. bKash decode = verified; everything else = planned/unverified.
- Never commit: real payloads, real account numbers, real NPSB tokens, `.env`, secrets.
- Commands: `pnpm install`, `pnpm build`, `pnpm test`, `pnpm typecheck`, `pnpm dev`,
  `pnpm vendor:edge`, `node scripts/check-sql.mjs`.
