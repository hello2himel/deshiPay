# Self-hosting deshiQR

deshiQR's HTTP API is **one stateless edge function**: payload + amount in, dynamic payload + QR SVG
out. This guide deploys it yourself. The frontend is yours — any static host works, and this repo
ships libraries plus a web component, not a hosted app. If you only need the browser path, you can skip
the server entirely and use the `deshiqr` package.

**What you need:** a [Supabase](https://supabase.com) project (free tier works for a demo), Node
`>= 22.18` and pnpm for building the repo, and the Supabase CLI.

> **No real data.** This repo is built around synthetic payloads from
> [`demo-payloads.md`](./demo-payloads.md): fake account `01000000000`, `DEMO STORE`, dummy NPSB
> tokens. Do not replace fixtures or examples with a real merchant QR. The payload is public data
> _once printed_, but keeping real samples out of the repo is a hard rule.

---

## 1. Build the repo

```bash
pnpm install
pnpm build                 # the npm package (payload + QR + element) and the browser bundle
pnpm test                  # optional but recommended
```

`pnpm build` writes `packages/deshiqr/dist/`: `index.js`/`index.cjs`/`index.d.ts`, `element.js`, and
the IIFE bundle `deshiqr.global.js`. The edge function does not import the package — it uses the
committed vendored copies in `supabase/functions/_vendor/`, so you can also deploy from a clean clone
without building.

---

## 2. Create the Supabase project

1. Create a project in Supabase. Pick a region close to your users (for Bangladesh:
   Singapore or Mumbai).
2. Note the **project ref** and **Project URL** (Project Settings → API). That URL is your API base:
   `https://<project-ref>.supabase.co/functions/v1/qr`.

You do **not** need the anon key, the service-role key, the database, Auth, or any secret for this
function. It is stateless and has no storage of its own.

---

## 3. Deploy the `qr` function

The function source is `supabase/functions/qr/`. It imports the dependency-free library sources from
`supabase/functions/_vendor/` (generated by `pnpm vendor:edge`; the files are committed).

```bash
supabase login
supabase link --project-ref <project-ref>

# Optional: regenerate the vendored library sources after editing
# packages/deshiqr/src/core or packages/deshiqr/src/qr.
pnpm vendor:edge

# Public endpoint: no key, no database.
supabase functions deploy qr --no-verify-jwt
```

`--no-verify-jwt` lets browsers call the endpoint without the project anon key (the payload is public
data). Omit the flag if you want every request to carry the anon key instead.

---

## 4. Configuration

There is exactly one optional setting:

```bash
supabase secrets set DESHIQR_CORS_ORIGIN=https://your-site.example
supabase functions deploy qr --no-verify-jwt   # redeploy for the change to take effect
```

| Setting               | Default | Purpose                                                                                        |
| --------------------- | ------- | ---------------------------------------------------------------------------------------------- |
| `DESHIQR_CORS_ORIGIN` | `*`     | `Access-Control-Allow-Origin` for browser callers. Set it to your site origin to tighten CORS. |

No database schema, no seed data, no service-role key, no merchant records. If you see documentation
elsewhere describing those, it is out of date — this repository only ships the stateless function.

## 5. Smoke test

Using the synthetic static payload from [`demo-payloads.md`](./demo-payloads.md):

```bash
curl -sS -X POST "https://<project-ref>.supabase.co/functions/v1/qr" \
  -H 'content-type: application/json' \
  -d '{"payload":"00020101021126470014bd.org.bb.npsb010202020420020311010000000005204601653030505802BD5910DEMO STORE6005Dhaka62060602FT80660014bd.org.bb.npsb0144ZGVzaGlxciBkdW1teSB0b2tlbiBBIG5vdCByZWFsISE=81660014bd.org.bb.npsb0144ZGVzaGlxciBkdW1teSB0b2tlbiBCIG5vdCByZWFsISE=6304295D","amount":500}'
```

Expected: `200` with `ok: true`, a derived `payload` (tag `01` = `12`, tag `54` = `500.00`) and a
`qr_svg`. Contract and error codes: [`amount-qr.md`](./amount-qr.md).

## 6. Use it from your frontend

Any static host works — a Vite/React/Next static export, plain HTML, or no frontend at all. Call the
function URL from your checkout/donation page:

```js
const res = await fetch("https://<project-ref>.supabase.co/functions/v1/qr", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ payload: merchantPayload, amount: cartTotal }),
});
const body = await res.json();
if (!body.ok) throw new Error(body.error.message);
document.querySelector("#qr").src = "data:image/svg+xml;charset=utf-8," + encodeURIComponent(body.qr_svg);
```

Or skip the network and do the same two steps in the browser with `deshiqr` / `<deshiqr-pay>` — see
[`embedding.md`](./embedding.md). No Supabase client, env vars or keys are needed either way.

## 7. Troubleshooting

| Symptom                                  | Likely cause                                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------------------------------- |
| Function returns `401` with no JSON body | JWT verification is enabled; send the anon key or deploy with `--no-verify-jwt`              |
| `404` / `Function not found`             | function not deployed, wrong project ref, or wrong route (`/functions/v1/qr`)                |
| `400 EMPTY_PAYLOAD` / `BAD_TLV`          | the request body is not JSON, or the payload is not a static Bangla QR string                |
| `400 CHECKSUM_MISMATCH`                  | the payload was damaged in transit or is not a Bangla QR payload; re-copy the static payload |
| `400 BAD_AMOUNT`                         | amount is missing, ≤ 0, > 99,999,999.99, or has more than 2 decimals                         |
| CORS errors in the browser               | set `DESHIQR_CORS_ORIGIN` to your site origin and redeploy                                   |
| Library changes not reflected by the API | run `pnpm vendor:edge`, commit the vendored files, then redeploy                             |
| `413 UNSUPPORTED`                        | the payload or body is larger than the function accepts — check what you are sending         |
