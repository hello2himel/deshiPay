# Self-hosting deshiQR

deshiQR's HTTP API is **one stateless edge function**: a payload plus edits in, the updated payload and
its warnings out. This guide deploys it yourself. The frontend is yours — any static host works — and
if you only need edits in the browser or on your server you can skip the function entirely and use the
[`deshiqr` package](../packages/deshiqr).

**What you need:** a [Supabase](https://supabase.com) project (free tier works for a demo), Node
`>= 22.18` and pnpm for building the repo, and the Supabase CLI.

> **No real data.** This repo is built around synthetic payloads from
> [`demo-payloads.md`](./demo-payloads.md): fake account `01000000000`, `DEMO STORE`, dummy NPSB
> tokens. Do not replace fixtures or examples with a real merchant QR. The payload is public data
> _once printed_, but keeping real samples out of the repo is a hard rule.

---

## 1. Build the repo

```bash
pnpm install
pnpm build                 # the npm package (update + validate) and the browser bundle
pnpm test                  # optional but recommended
```

`pnpm build` writes `packages/deshiqr/dist/`: `index.js`/`index.cjs`/`index.d.ts` and the IIFE bundle
`deshiqr.global.js`. The edge function does not import the package — it uses the committed vendored
core in `supabase/functions/_vendor/`, so you can also deploy from a clean clone without building.

---

## 2. Create the Supabase project

1. Create a project in Supabase. Pick a region close to your users (for Bangladesh: Singapore or
   Mumbai).
2. Note the **project ref** and **Project URL** (Project Settings → API). Your API base is:
   `https://<project-ref>.supabase.co/functions/v1/update`.

You do **not** need the anon key, the service-role key, the database, Auth, or any secret for this
function. It is stateless and stores nothing.

---

## 3. Deploy the `update` function

The function source is `supabase/functions/update/`. It imports the dependency-free core from
`supabase/functions/_vendor/` (generated by `pnpm vendor:edge`; the files are committed).

```bash
supabase login
supabase link --project-ref <project-ref>

# Optional: regenerate the vendored core after editing packages/deshiqr/src.
pnpm vendor:edge

# Public endpoint: no key, no database.
supabase functions deploy update --no-verify-jwt
```

`--no-verify-jwt` lets browsers call the endpoint without the project anon key (the payload is public
data). Omit the flag if you want every request to carry the anon key instead.

---

## 4. Configuration

There is exactly one optional setting:

```bash
supabase secrets set DESHIQR_CORS_ORIGIN=https://your-site.example
supabase functions deploy update --no-verify-jwt   # redeploy for the change to take effect
```

| Setting               | Default | Purpose                                                                                        |
| --------------------- | ------- | ---------------------------------------------------------------------------------------------- |
| `DESHIQR_CORS_ORIGIN` | `*`     | `Access-Control-Allow-Origin` for browser callers. Set it to your site origin to tighten CORS. |

No database schema, no seed data, no service-role key, no merchant records, and no QR rendering. If
you see documentation elsewhere describing those, it is out of date.

## 5. Smoke test

Using the synthetic static payload from [`demo-payloads.md`](./demo-payloads.md):

```bash
curl -sS -X POST "https://<project-ref>.supabase.co/functions/v1/update" \
  -H 'content-type: application/json' \
  -d '{
    "payload": "00020101021126470014bd.org.bb.npsb010202020420020311010000000005204601653030505802BD5910DEMO STORE6005Dhaka62060602FT80660014bd.org.bb.npsb0144ZGVzaGlxciBkdW1teSB0b2tlbiBBIG5vdCByZWFsISE=81660014bd.org.bb.npsb0144ZGVzaGlxciBkdW1teSB0b2tlbiBCIG5vdCByZWFsISE=6304295D",
    "edits": { "amount": 500, "reference": "BILL123" }
  }'
```

Expected: `200` with `{"ok": true, "payload": "…6304DB6A", "warnings": []}` — tag `01` is `12`, tag
`54` is `500.00`, the `62/01` reference is `BILL123`, and the checksum is re-sealed. Contract and
error codes: [`api.md`](./api.md#http-endpoint).

Validate-only (no edits) returns the same payload with its warnings:

```bash
curl -sS -X POST "https://<project-ref>.supabase.co/functions/v1/update" \
  -H 'content-type: application/json' \
  -d '{"payload": "<your payload here>"}'
```

## 6. Use it from your frontend

Any static host works — a Vite/React/Next static export, plain HTML, or no frontend at all. Call the
function URL and render the returned payload however you like:

```js
const res = await fetch("https://<project-ref>.supabase.co/functions/v1/update", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    payload: merchantPayload,
    edits: { amount: cartTotal },
    warnings: true,
  }),
});
const body = await res.json();
if (!body.ok) throw new Error(body.error.code + ": " + body.error.message);

// body.payload is the updated payload; encode/render it with your own QR tool.
renderQr(body.payload);
for (const warning of body.warnings) console.warn(warning.code, warning.tag, warning.message);
```

No Supabase client, env vars or keys are needed. For client-side or offline edits, use the same two
functions from [`deshiqr`](../packages/deshiqr) — see [`api.md`](./api.md).

## 7. Troubleshooting

| Symptom                                   | Likely cause                                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Function returns `401` with no JSON body  | JWT verification is enabled; send the anon key or deploy with `--no-verify-jwt`                     |
| `404` / `Function not found`              | function not deployed, wrong project ref, or wrong route (`/functions/v1/update`)                   |
| `400 EMPTY_PAYLOAD` / `BAD_TLV`           | the request body is not JSON, or `payload` is not a well-formed Bangla QR string                    |
| `400 MISSING_FIELD` / `CHECKSUM_MISMATCH` | the payload is truncated, damaged in transit, or has a stale checksum; re-copy the original payload |
| `400 DUPLICATE_TAG`                       | the payload contains the same tag twice at one level; fix the source payload                        |
| `400 BAD_AMOUNT`                          | amount is `≤ 0`, `> 99,999,999.99`, not numeric, or has more than 2 decimals                        |
| `400 BAD_TAG` / `BAD_VALUE`               | an edit key is not a valid tag path, targets `63`, or its value cannot be encoded                   |
| CORS errors in the browser                | set `DESHIQR_CORS_ORIGIN` to your site origin and redeploy                                          |
| Library changes not reflected by the API  | run `pnpm vendor:edge`, commit the vendored files, then redeploy                                    |
| `413`                                     | the request body is over 16 KB or the payload is over 4096 characters (`UNSUPPORTED`)               |
